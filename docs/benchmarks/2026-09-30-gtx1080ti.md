# Benchmark on the GTX 1080 Ti, 2026-09-30

Created 2026-09-30 21:53, MAT 0.2.0, torch 2.8.0+cu126, GPU NVIDIA GeForce GTX 1080 Ti, 580.178.04, CPU x86_64

Release test for MAT 0.3.0, commit 920667d, public datasets only (no corrected reference of our own episodes yet).
Two partial runs: transcription systems on FLEURS and Bundestag, diarization systems on VoxConverse and AMI. The
`default` system is MAT's defaults (whisper large-v3-turbo, pyannote community-1 exclusive).

What we take from it:

- whisper stays the default transcriber. Parakeet with its default 600 s pieces loses sentences in packed files
  (21.5 % WER on FLEURS). With 30 s pieces it's slightly better than whisper on FLEURS (6.6 % vs 6.9 %) and faster,
  but twice as bad on German parliament speech (20.2 % vs 10.1 %), and it needs over 8 GB of GPU memory.
- community-1 stays the default diarizer. DiariZen is better (5.2 % vs 8.2 % DER on VoxConverse, 13.3 % vs 16.9 %
  on AMI) but half as fast, non-commercial and in its own environment, so it's the option for the best result.
- Sortformer is clearly worse than both on VoxConverse (23 to 25 % DER, 4 to 5 speakers off), close on AMI only with
  300 s pieces. Streaming Sortformer is no better than the piece-wise one.

## How to read this

- RTFx: seconds of audio per second of processing, model loading included.
- Peak GPU: highest memory of the MAT process in nvidia-smi, including the CUDA context.
- WER: word errors over the whole file after lowercasing and removing punctuation and fillers (uh, äh, ...). Numbers aren't normalized, 5 and five count as different words.
- cpWER: like WER, but every reference speaker is compared only with the words of the system speaker assigned to them, so wrong speakers count as errors.
- DER: missed speech, false alarms and speaker confusion over all reference speech, overlaps included.
- speakers off: average difference between the number of reference and found speakers.
- Rates are totals over all files of a dataset, so long files weigh more.
